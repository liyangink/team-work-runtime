## 3. Findings（覆盖缺口）

### F-1（risk）台账门槛 7「真实 DSH 人工门 rework 复验」未显式落点（§6-5 部分承接）
- statement：台账唯一非自动化门槛、直接对应事故现场的门槛，在方案 §5 与 §6 无显式验收落点；§6 第 5 步继续当前任务（该任务正处于人工门 rework 现场）部分承接了真实 DSH 复验路径，但未声明其即复验、也无复验判据。
- 定级：按跨包统一口径（台账七条验收门槛之一、§5/§6 无显式落点、§6 第 5 步仅部分承接）定为 risk，summary 终裁并回写。
- evidence：v2-e2e-findings.md:122「高风险状态恢复完成后再做一次真实 DSH 人工门 rework 复验」；方案 §5（102-111 行）八条验收全为自动化/迁移/回归；§6 第 5 步（119 行）「迁移后继续当前方案评审任务：Challenger 完成在途 w24 评审 → 推进 → Expert 重裁 → 人工门批准卡」未声明判据（journal 不增长、原 Owner 可解析、重复推进/混用/并发同卡）。
- 归因：§5/§6 覆盖缺口。
- 最小修复：§6 显式新增「真实 DSH 复验」步骤（或声明第 5 步即复验），并写明判据：首次推进只写一批；任意次 run/dispatch-plan 混用与并发返回同一 wait-inflight 且 journal 不增长；续派仍解析原 Owner。

### F-2（blocker）台账 P0-5/门槛 4 的「不同 digest 多报告出用户选择卡」无落点
- statement：已结波内 digest 不同的多份历史报告如何收敛，方案无机制；报告不可变第三态（台账 P1-3）同步缺失。
- evidence：v2-e2e-findings.md:87「多报告且 digest 不同才出用户选择卡」、:119 门槛 4「零报告、一个报告、同 digest 多报告、不同 digest 多报告四类均有确定、可审计、无删除的恢复结果」；方案 F9（81-85 行）只定义成波合并规则；F3（49 行）retire 只允许作废当前未结波，已结波不在其范围；F7（70-74 行）只定义同 key 两态。
- 归因：F9+F3 之间缺「历史冲突报告收敛」子项；F7 缺第三态。
- 最小修复：F9（或 F3）补一条：同波多 key 已接受且 digest 不同 → 出用户选择卡（保留一、其余写 dispatch-superseded）；§5 第 7 条改为四类矩阵验收用例。

### F-3（risk）F5 指纹近似是缓解而非根除；台账 P1-2 因果链为无声遗漏
- statement：F5 可识破「同内容重交冒充」，但「决定前旧 key 交无关改动（指纹变化）」仍通过判定；台账建议的 causeDecisionId/waveRef 因果引用未实施，且未列 §8。
- evidence：v2-e2e-findings.md:53「只有绑定该决定的派单报告才能完成本次返工；判断使用 journal seq/引用，不使用墙钟时间」、:92（P1-2）、:109（相邻场景「必须带本次 causeDecisionId 才能消费返工」）；方案 F5（56-61 行）判据为「当前制品指纹 ≠ 决定的 artifactFingerprint」——旧 key 重交同内容时指纹不变→识破（复现 4 修复形态成立），但迟到报告带无关改动时指纹变化→误判已返工。
- 归因：F5 对 V3-E2E-04 是代理判据；P1-2 未落任何 F 项、未列 §8。
- 最小修复：二选一并写明——①F5 补返工波与决定的绑定（waveId 可从决定推导，或派单写 causeDecisionId）；②§8 如实后置「完整因果引用」，并标注 F5 为过渡近似、边界为「无关改动冒充」仍可穿透。

### F-4（risk）§5 验收对门槛 2/6 的映射弱化
- statement：多包部分交付、重启恢复、二次 rework 因果隔离在 §5 无显式验收条目。
- evidence：v2-e2e-findings.md:117 门槛 2「单包、多包、部分交付、重启恢复均满足一逻辑波一批派单；多包只等待未交付包」、:121 门槛 6「第二次人工 rework 也不能被第一次的报告消费」；方案 §5-1（104 行）只写「journal 不增长」，§5-4（107 行）只写「决定前旧 key 重交同内容/不同内容」两种形态。
- 归因：§5 验收条目与门槛的粒度不对齐。
- 最小修复：§5 补「多包部分交付（只等待未交付包、不重派已交付包）+ 进程重启重放原 key 不扩波」与「连续两次人工 rework 的因果隔离」两条验收。

### F-5（info）方案「根修不逐条打补丁」声称需校准
