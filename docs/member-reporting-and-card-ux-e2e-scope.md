# 成员汇报与卡片改造：实机验证范围

本轮独立核验本机 DSH 0.2.2-rc.5 上的宿主接缝，以及当前工作区源码在隔离 headless 中的实际行为；不改产品、现有测试或本机安装。验收对象是 [已批准设计](<member-reporting-and-card-ux-design.md>) 中的成员汇报、人工返工额度、意图首卡和呈现，不是客户端整套兼容性或模型总体效果。

| 组别 | 驱动与验收证据 |
| --- | --- |
| 宿主接缝 | 用 `ELECTRON_RUN_AS_NODE=1`、`DSH_TEST_HOST` 跑 [接缝测试文件](<../tests/dsh-plugin-e2e.test.mjs>) 全量，不筛选、不跳过；保存 TAP、stderr、退出码、宿主版本和输入散列。验收要求 10 通过、0 失败、0 跳过；若文件实际项数不同或有失败，保留原始计数，不凑数。 |
| A：途中汇报与必要协调 | 主样本让正式 Owner 尝试一次无效播报，再观察软提示、后续播报决策、目标方收信和唤醒；验证 Lead 主动问询与纠偏。另一个独立样本让 Owner 在未报告时尝试必要求助，收到软提示后同 turn 后一 Step 原样重发；对账双方收信和恢复交卷。分别统计尝试、未发送、原生接受、实际递达、消息唤醒、正常结项唤醒。 |
| B：意图确认 | 明确指定入口、目标、可写文件与模型的样本使用 `--user-direction`：核对直接授权落盘在实际首派之前，且从未签意图卡。有明确口径差异的对照同样传已知字段，不代答：核对原生工具结果、只读投影、日志冻结正文及七个固定栏目，证明停卡时没有派单。 |
| C：人工返工后的自主额度 | 默认三轮自主额度、一个核心审查阶段、一个 Owner：第 1 轮过真实评审进入人工门，合成外部用户要求第 2 轮返工；真实 Challenger 在第 2、3、4 轮因缺追踪编号提交返工。展示第 4 轮、自主 3/3 时，经真实原生工具只确认一次该上限卡，随后实际收第 5 轮派单并登记。保留两个人工门决定和额度决定的不同 ID，分别核对，不把其他决定算作第二次追加。 |
| D：呈现和跨块 | 原生回执区分派发、普通状态、真正人工审核、固定意图首卡、机械上限和完成，按 Unicode 字符核对正文长度、写作短段与是否重复；详情链接单独计量。另用已装配的真实原生工具调用大文本 CLI，不重分块，保存实际 stdout 字节与 data 边界，核对多字节在真实分界处且卡正文逐字回传。 |

所有模型样本装配同一工作区源码和本地依赖副本，独立 `HOME`、`DSH_HOME`、测试项目与日志均在 `/tmp` 下；只从宿主原生凭据解析器读取指定引用，不传个人资料给模型，不复制、打印或在配置中写凭据值。Lead、Owner、Challenger、Expert 均需有真实请求头 `zai-coding-cn/glm-5.3`、强度 `max` 以及提供方响应记录，不能以配置或角色标签代替。只核查本轮新生成的会话和任务日志，不遍历真实会话或真实任务内部状态。

不测桌面/Web 卡片像素或客户端点击链；外部答卡是绑定实际卡 ID 的合成用户输入，不证明真人身份授权。用例 B 测试了显式信息差，不外推至所有自然语言纠偏、意图增量和角色冲突。A 不做新旧版本流量配对，结果只说明样本中的抑制及恢复，不外推整体消息或 token 降幅。跨块是生产工具及 CLI 进程的无模型压力样本，与真实模型例行回执分别报告。

- 不改 [历史评测目录](<../evals/twr-external-headless-glm53-e2e/>)、产品源码、现有测试、全局 profile 或已安装插件；不变更仓库清单、不提交或发布。发现问题由 Lead 分流，不在测试包顺手修复。
