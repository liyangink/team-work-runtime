# TWR headless 隔离实机验收范围

**离线通过不算 GLM 实机验收。** 以当前工作区副本实测双包正式波次、两类按包返工、交付清单增删和最终人工门；必须先在获准的 macOS 测试会话或[外部终端](code/README.md)通过原生写隔离，才提交模型请求。

依据为[冻结设计 §1](../../runtime-v3/twr-framework-architecture-design.md#L5-L11)、[§9 矩阵](../../runtime-v3/twr-framework-architecture-design.md#L207-L240)、[前序验收报告](../twr-headless-real-host-validation/results.md)和本派单约定。复用前序七个 CLI 用例和其合成故障证据，不覆盖之前报告；新增同一闭环内的跨 key 回执增删和 G-3 原文交接断言，复跑更新后的离线测试。G-1 不加阻挡旧 key 的新门禁，G-2 不更改决定权威，不把缺事件旧报告问题判为已解决，不改产品、冻结设计、历史报告或真实配置。

## 分层、版本和边界

| 层次 | 判定口径 |
|---|---|
| 外层测试团队 | Owner/独立 Challenger 均使用派单指定的 GPT-6.2-Sol/max，Expert 只占位；本 Owner 不能派发或评审自己。制品须由 Challenger 独立复核，经外层人工门验收。 |
| 真实独立宿主 | macOS 上指定 DSH 0.2.2-rc.5，真实 CLI 的同一引导函数和 headless runner，独立物理临时项目、HOME、DSH_HOME、单独 profile，无 GUI、无真实任务和设置。运行中检查选中源码的整树 SHA、实际副本、profile 和场景不漂移。 |
| 原生隔离前置 | 同一 headless 进程等待 stdin 时，先运行原生 Bash；随后从实际加载的原生工具分别调用 tw help 和一次不存在任务的 tw-dispatch。两个原版 CLI 入口都由测试启动器使用同一 DSH 服务生成的 Seatbelt 规则约束，CLI 同进程和后代各自证明仓库根/子目录已有文件写式打开拒绝、仓库/HOME 随机名独占创建拒绝及隔离项目写入允许。原生 write 的同一文件变更前检查须拒绝两个真实路径，且实际原生 write 能在项目创建并清除哨兵。三类入口任一缺证，或内层执行器不是原生执行器，均不提交提示。规则不回退、不修改既有真实文件，也不把文件写限制当作读隔离或封网。 |
| 内层真实角色 | Lead、Owner 甲、Owner 乙、Challenger、Expert 均锁定 GLM-5.3/max 的指定提供方。意图卡核对角色登记和逐包物化，实机以各会话的 request/header 及提供方响应为准；按父子 ID/正式派单 key 对到原生登记和实际收单；插件配置、描述符、徽标都不能替代请求头。 |
| 离线证据 | 要求最新源码副本进程级 CLI 及相关仓库自动套件通过；模拟宿主、故障注入、合成决定不得当作真实模型、生产宿主行为或真实用户授权。 |

## 七组能力判据

| 组 | 本任务验证设计 |
|---|---|
| ① 派发、对账与恢复 | 外部回合重启同一 Lead，核实首波同批两包、九个正式派单 key 的实际唯一收单、原角色映射与报告；普通恢复路径以实际轨迹为限。活/冷/已报/未知、同 key、部分失败与停写/并发以离线和宿主替身分列。 |
| ② 强类型、返工范围与 G-3 | 离线验证旧形状拒绝及同 key 修正；实机首测保留同步拒绝后同 key 修正的证据；复跑只补充公开参数形状，不放宽既有核验。真实场景按 [任务剧本](code/scenario.md) 让 Challenger 仅点甲包、Expert 在 Challenger 接受后仅点甲包。每轮从结构化 finding 计算原文，对接收正文核验精确一次、本包 context 在场、他包 context 不外溢，不靠摘要转述。 |
| ③ 完整清单、回执及新鲜度 | 甲包先登记主文档与旧页，下一 key 重列主文档／加入索引／移出旧页，回执只显示索引新增、旧页移出；磁盘旧页字节保留、后续审查只见当前集；Expert 下一 key 只改内容，路径不报增删。在实际持久会话日志中按派单与报告序号绑定成功原生 write/read，核验首轮状态、每份当前读件、创建/更新操作和登记原始 SHA，拒绝预置文件、旧版本、错角色或缺证据；不承诺锁外改写或 ABA。旧协议×blocked、跨阶段与跨包用离线用例验证。 |
| ④ 授权刷新及多卡 | 离线刷新、按 ID 决定、单卡静止、旧指纹漂移、过期拒绝、收口和重新评审测试。外部场景不人为制造真实源漂移，不把普通双人门当作刷新授权验证。 |
| ⑤ 多包计划及恢复 | 外部检查独立并行包、互斥范围、无关乙包无返工；离线补依赖解锁、按包阻塞与恢复、F-10 模型回滚、并发计划。不因此声称 G-2 已解决。 |
| ⑥ 作废、旧任务、规则 | 离线覆盖作废回退、可核验历史快照、旧增量歧义、规则来源；外部实际 skill 与原生 help，未安排真实旧写者切换、恢复业务任务或安装旧版本。 |
| ⑦ 完整两包链 | 意图卡外部确认 → 首派 → 甲乙首交 → Challenger 定点返工 → 甲包跨 key 清单增删 → Challenger 复审 → Expert 定点 → 甲包仅内容更新 → Challenger 重审 / Expert 重裁 → 最终人工门外部确认 → 完成。交互入口由外部终端操作者明确输入；经本轮明确授权的非交互入口由外部测试驱动在复核每次真实停门之后，按当前卡提交批准短句，并独立标记为测试输入。Lead 不代答、不提前派发、不启用自动 Goal；E2E 仅合成文本的明确 skip 路由。 |

外部脚本把可执行预检、模型流程和只读复核分开；不做真实故障注入、业务系统写入或规模性能测试。超时、隔离失败、回执与日志无法对账或人未批准，均保留证据并暂停，不回退到不安全模式。复跑和首测分别留档；独立 Challenger 可对通过样本只读重算，不需要重发模型请求。逐项现状见[结果](results.md)。
