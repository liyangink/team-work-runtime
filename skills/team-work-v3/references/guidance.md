# 派单引导库（guidance）

Runtime 生成派单时按「角色 + 场景」自动注入公共引导，让成员开工前拿到执行纪律与专业要求。引导只做增强：不改变派单边界、可写范围与检查规则，与派单正文冲突时以派单正文为准。

验收基线由 Runtime 从现有 intent 与包计划原样投影：目标、约束、排除项，Owner 的本包 done 或组合评审/Expert 的各包 done 与交付状态；无包不臆造完成标准。首派、续派、全量恢复和在途重建均携带一次当前基线。角色/场景引导说明怎样依此判断，不能增加用户授权或理想验收条件；详细分流见[场景指导](scenarios.md#验收基线与意见分流)。

## 检索层级

- 角色引导：`team-work/guidance/roles/<role>.md`，键 = 派单角色（owner | challenger | expert）。注入所有对应角色的派单（含续派与在途重建）。
- 场景引导：`team-work/guidance/scenes/<sceneId>.md`，键 = 阶段声明的 `teamScene`（如 design、design-review、implementation、test）。注入该场景阶段的所有派单——Owner 按此执行，Challenger/Expert 按同样标准审视；design-review 区分方案标准与审查报告职责，不另造方案。
- 缺失的目录/文件静默跳过，不阻塞派发；引导文本是数据不是代码，不参与门禁判定。

## 分层覆盖

包内默认引导为基线；项目根 `team-work/guidance/` 下的同名文件逐文件覆盖，项目只需放置要自定义的条目，其余保留基线。

同名文件整体覆盖，升级不会静默替换项目自定义文件；使用自定义引导的项目需核对并合并新增规则。自定义覆盖可能省去角色细则，但统一派单验收基线仍由 Runtime 生成。

## 明晰规则自动带入

专业引导之外，Runtime 从根包[公共规范](../../clarity-guidance/output-standard.md)和[专项审阅规则](../../clarity-review/references/review-rules.md)的唯一必读段提取原文，以 requiredGuidance 只读输出送达，不依赖主动 skill 调用、宿主同名来源或项目覆盖。所有成员公共；review/verdict 或 design/design-review/spec-review/code-review Owner 加专项，自定义无这些事实仅公共。Lead 普通汇报公共，awaiting-user/blocked 加专项，重复终态查询也在场；机械回执不重复附段。

DSH 同消息规则块及 CLI human/JSON 使用相同投影，完整 skill、示例和独立账本不随派单加载。每实际消息各适用段一次、最多两段，同操作按需读一次，无跨会话已读标记；两段不限制重要问题数量。缺文件/坏标记显示来源诊断、不谎称送达，不改授权或原门禁。深读仅沿输出的准确资源路径；工具外聊天/原生助手无自动覆盖承诺。

## 热变语义

引导文本在每次真正派发与在途补发重建时重新读取，无缓存：修改引导文件只影响此后派发与在途补发重建的文本，不追溯已派发文本（已派发的成员仍按实收文本执行）。

不为让新规则生效强行重派在途任务。新增基线与引导只有实际送达后才影响成员；文本回归证明输入到达，不证明模型一定遵守，也没有自动授权检查或范围外识别。

## 扩展方式

- 修订某角色/场景的引导：直接编辑对应 md 文件，下次派发生效。
- 新增场景引导：在 `scenes/` 下新建与 `teamScene` 同名的 md 文件。
- 新增角色引导：在 `roles/` 下新建与派单角色同名的 md 文件。
- 引导文本用中文、通用、脱敏：不引用特定项目、账号或环境信息；公开的技术概念（如 JUnit 的 @DisplayName）可以借用。
