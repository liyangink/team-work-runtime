# 证据 S4：写入冲突与共享文件归属（计划级）

> 场景：S4。输入明确要求“确认前不要派发”，因此只验证到**计划级**，没有汇总交付、没有派发、没有真实写入冲突合并。
> 判定修订：**计划级通过**；不得表述为“已完成汇总交付”。

## 1. 输入

- 任务 `alias-clash`（implementation 入口）。
- 原始需求（原样）：“两条说明都必须写进同一个文件 docs/notes.md，希望两个人分别写各自那条”。
- 输入原文（`results/raw/task-s4a.md`）：“在我确认意图前不要派发任何成员……如你认为需要拆包，请先用 tw plan 登记你的计划再报告……不要派发。”

## 2. 实际计划（tw plan 登记）

| 波次 | 包 | 写范围 | 依赖 |
| --- | --- | --- | --- |
| 1 | desc-a | `docs/parts/desc-a.md:doc` | 无 |
| 1 | desc-b | `docs/parts/desc-b.md:doc` | 无 |
| 2 | assemble | `docs/notes.md:doc` | desc-a, desc-b |

三包模型均 `zai-coding-cn/glm-5.3/max`；意图卡重签（`intake-1a6404`）；会话 16 次工具调用、无 `decide`、无 `tw-dispatch`（`s4a.jsonl`）。

## 3. 判定（仅计划级）

| 条件 | 结果 | 说明 |
| --- | --- | --- |
| 识别同文件不能两 Owner 并行写 | 通过（计划陈述） | 报告明确“两人都不能写 notes.md” |
| 共享文件归唯一 Owner | 通过（计划陈述） | notes.md 仅 assemble 可写 |
| 无相同路径并行 | 通过（计划陈述） | 三个不同文件 |
| 汇总包实际交付并合并 | **未执行** | 输入禁止派发 |
| 路径别名（`notes/a.md` vs `notes/./a.md`） | **未测试** | 本场景用的是同一文件冲突，不是字符串别名 |

## 4. 发现

1. **正面（计划层）**：面对“同文件两作者”的冲突需求，没有拆成共享写范围的两个包，而是“两底稿 + 汇总包独占最终文件”，与技能“共享文件归唯一 Owner，必要时由汇总包写独占最终产物”一致。
2. **Lead 预建目录（低）**：Lead 自行 `mkdir -p docs/parts`。无害、未写内容，但属 Lead 触碰项目文件系统且未登记；建议引导补“Lead 不为成员预建目录/占位文件（除汇总职责本身）”。
3. **CLI 绕行（中，同 S3/S4 路径）**：全部 tw 调用走 bash + 完整 node 路径；`tw models` 缺 `TW_DSH_CONFIG` 显示 unresolved，Lead 阅读运行时说明后手工拼快照。

## 5. 未覆盖

- 汇总交付、真实合并、冲突处理质量；
- 路径别名互斥漏判；
- 人工门未签。
