# 无 Web CLI 实机验收范围

**实机前置不满足，本轮交付离线证据与缺口，不给出实机通过结论。** 验收基线为冻结设计 [§1](<../../runtime-v3/twr-framework-architecture-design.md#L5-L13>) 与 [§9](<../../runtime-v3/twr-framework-architecture-design.md#L207-L240>)、[后续修复审查](<../../docs/reviews/twr-framework-review-fixes-code-review.md#L33-L115>)及外层派单的最新澄清，覆盖整次重构，不只测返工正文。

## 角色与边界

- 外层为正式测试任务：协调 Lead 不当作内层被测 Lead；外层 Owner 与独立 Challenger 配置为 GPT-6.2-Sol/max，Expert 仅是未用占位，不派发、不另开终审。Owner 仅提交本包材料，不代 Challenger 核验、不批准正式任务的最终人工门。
- 内层是本应单独运行的 DSH 无 Web CLI 用例：Lead、两包 Owner、Challenger、Expert 都必须用派单指定的精确 GLM-5.3/max 路由；任务级/逐包模型登记和各角色实际请求头是两种证据，必须同时核验。Node 夹具只用虚构模型标识，不发出模型请求；任何卡片答复都仅是合成输入，不是实际用户授权。
- 不改产品、冻结设计、历史评测、真实安装或用户配置，不动真实项目数据，不新增 G-1 守卫或改动 G-2 决策权威。绝不靠路径名、提示约束或运行前后没观察到差异来替代写拒绝证据。

## 验收顺序与证据等级

1. **安全前置**：在实际拟运行的 DSH 命令与后代工具链，证明真实仓库和 HOME 拒写、虚构项目可写、同限制对子进程和孙进程仍生效；任一失败/无法验证就停止模型分支。核对独立 HOME、profile 和无 Web 顶层会话/续聊；源码副本指纹必须等于宿主实际加载指纹。查不到精确模型权限也应停止，不换模。[前置结果](<code/safety-evidence.md>)。
2. **真实宿主**（本轮阻碍）：假如前置通过，用两包虚构资料检查实际首派 key→session 映射、成员收到的正文和真实请求头、待决静止、独立进程续聊及跨轮续派。安排可独立识别的本包/全组必修意见；核验实际提交的报告、目标包和实际收件原文，既不漏本包/全组意见，也不夹入他包。返工保留完整清单，重审、重裁后停在人工门。真实模型没有触发的分支仍列缺口，不用脚本代演冒充。
3. **真实 TWR CLI 合成夹具**（无 DSH）：用当前源码字节等价副本的实际 bin，以新 Node 进程调用 CLI。验证同步拒绝、报告版本和文件字节、按包/全组返工、普通/全量与冻结正文、多卡、按包恢复、新用户门。测试夹具只选择真实回执中的卡 ID，明确标识模拟步骤。用虚构 HOME 和专属临时项目，不访问正式任务内部状态。
4. **模拟宿主与既有自动测试**：前者执行真实绑定逻辑但以替身控制会话状态/事件/回执、竞争及投递失败；后者包括纯函数、真实 CLI 入口函数、合成文件和定点异常。覆盖文件变化、迁移/作废、回滚/重建、门禁和依赖等。模拟的即时收单、空记录或注入 I/O 失败不能证明真实宿主的持久化时序、故障恢复或恰好一次。

[结果和设计逐项矩阵](<results.md>)区分通过（限定证据类型）、失败/保留风险、阻碍、跳过和未执行。脚本执行方式与原始证据索引见[离线复跑说明](<code/README.md>)。
