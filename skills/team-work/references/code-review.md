# 代码 Review

审查视角与成本档位正交：预算只影响由谁承担，不能删除视角。非作者 Senior 或 Expert 挑战问题集，非作者 Expert 给出整体技术裁决。

## 八个视角

1. **需求与变更摘要**：需求覆盖与范围外行为。
2. **缺陷与安全**：正确性、竞争、注入、权限、数据泄露与资源耗尽。
3. **错误处理**：异常、重试、超时、降级、清理与可恢复性。
4. **逻辑推演**：正常和失败路径的状态、数据与控制流。
5. **测试覆盖**：需求、边界、失败路径、并发与集成接口。
6. **类型与不变量**：边界、空值、序列化、状态机与跨层契约。
7. **规范与合规**：仓库规则、代码风格、兼容、许可证、隐私与领域规范。
8. **影响范围**：调用方、配置、迁移、性能、部署、回滚与下游行为。

## Finding 与复核

每个可执行 finding 必须有位置、归因、严重级别、置信度、触发条件、影响、证据、修复、回归测试和验证步骤。无触发条件或证据的猜测只能作为待确认风险。

先固定审查范围和比较基线，成员独立审查，再由挑战者检查重复项和归因。修复后由非原报告作者验证；不把纯偏好包装成缺陷，也不把实现成本、代码风格、可读性、代码结构、性能风险、业务风险、过度设计或遗漏扩张成无关重构。
