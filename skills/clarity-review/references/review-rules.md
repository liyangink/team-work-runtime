# 明晰审阅规则

通用表达只引用 [公共规范](../../clarity-guidance/output-standard.md)。下面必读段供 TWR 原文提取，也供独立审阅使用；详细资料不再另定义相同规则。

## 明晰审阅必读

查已确认意图、比较基线与当前产物，扫描全部重要候选：目标范围、用户行为、验收约束、权限数据、对外契约、架构代价、撤销恢复、前提缺口和跨产物偏离。读取必要原始证据与上下文；高影响未知不能因低置信删除。

先查基线及授权内证据，再分为：依据基线可消解（纠偏或建议，不重问原方向）、代理待核查（范围/动作/升级条件）、责任方执行项（责任/完成条件）、条件触发项（触发/最晚准备阶段）、人工方向决策（当前审核人必须作真实取舍）。先查现有监控和工具，不默认重建；责任未知标未知，不招人或联系他人，不猜分钟截止。五去向只是语义，不覆写 TWR 本轮阻塞/非阻塞/范围外分流。

方向选择与核心阻碍独立：安全、数据、可执行性未知须首屏说明影响、核查动作和升级条件，不能用“代理处理”隐藏。阻碍写动作与门槛，不用接受 checkbox；人工选择给建议/备选、代价和直接证据。重要事项无机械数量上限，完整候选留现有资料并给入口，不紧接首屏总表。

分清方向反馈、修改落实、产物符合性、证据/测试验证。要求修改不是接受新版，改完、相符或测试通过也不是接受；已落实纠偏无新取舍就报结果复核/未验证，不再问旧选择。展示不等于已读，明确接受只覆盖其修订、范围和条件，不授权部署。

核查只限当前授权与既有职责，会修不等于获修复权。TWR 用原方案/报告/用户决定，不另建独立账本或权威状态，Lead 不修技术或改成员结论；批准正文冻结，不为清单记账改正文/评审链。无新方向、纠偏落实、语义等价均不能跳过现版人工批准或指纹重批；awaiting-user 静止后不调查、派发、轮询、代答或推进，须新用户输入恢复。

## 基线、候选与证据的核验

意图基线回答应该做什么，比较基线回答这次变了什么：需求对用户目标/业务/验收；方案对已确认需求、架构与约束；代码对已确认需求/方案及前后代码和必要调用链。AI 草稿和当前代码不自动变成意图。没有旧版不声称新增/未变，没有确认基线就注明。

记录实际文件哈希、不可变文档版本或 Git base/head 与未提交内容快照，及规则版本。分支名、可变链接、时间戳不能单独证明内容身份。审核前和发送前核对快照；证据包含来源、版本、位置及短摘录，缺口还须引用产生义务的要求和已查范围。

必读段的九类对应 R01–R09 扫描视角，既查显式选择也查遗漏、弱化和例外失效；不是九个角色，也不要求每类产一项。可独立接受的选择分别成项，同因症状仅在简报合并，原归属及处置仍可查。行数、文件数、置信度和普通进度不决定是否重要。证据无法取得时说明缺什么，保留重要候选；已检查范围不能证明全无遗漏。

人工选择只有在证据仍不能消除取舍、属于本次审核人职责、当前或最近准备阶段必须选择时才提问。条件/执行项在最晚门槛前未准备好应显示阻碍；确需结果验收时说明是结果复核，不假装又有方向选择。可呈现统计但须按当前资料核对，不强求每份报告都有数字。

## TWR 上下文与批准

上下文必须有明确任务、阶段和范围，不凭仓库名推断。事实不可得就说明限制，不静默切独立模式。完整候选、去向和证据留在原授权报告或未批准方案；短简报给现有资料链接，完整方案不拆成第二批准基线。

四类事实仅分别引用已有决定、制品、报告及真实验证资料，缺证据标未验证，不声称 Runtime 增加四维状态或逐项 ID/revision。逐项接受不自动调用 tw decide，也不等于阶段批准；明确整份方案批准可作其范围依据，不能谎称逐项已读或自动全勾。

批准后普通反馈、阅读和阶段记录引用现有事实或已有适当报告，不主动制造正文/评审链变化。真实需求/范围/方向变化修订并走原重批；任何实际登记制品或评审链指纹变化仍由原门判断。准备决定材料前的核查与正式静止等待须区分。技术审查不新增角色、轮次、固定视角或工具参数，原专业合同保持。

独立持久审阅的全部记录、迁移和恢复判据见 [独立记录](standalone-records.md)，仅该模式读取。
