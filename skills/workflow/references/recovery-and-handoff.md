# 恢复与交接

## 恢复

1. 运行 `doctor`，再显式读取任务、阶段、revision、门禁和工作项。
2. 用 `context render` 获取最小索引，按当前动作读取原始制品。
3. 对照事件与制品确认最后一次已提交或已验收的动作；不要仅凭聊天历史推断。
4. 未验收工作项保持待验收或返工，不自动视为完成。
5. 平台会话失效只影响执行载体，不改变任务、工作项或制品身份；平台恢复方式从 Platform Profile 增量指南读取。

## 人工等待

以下情况必须明确暂停并请求用户：用户预先指定的确认点；需求存在会改变结果的歧义；不可逆、高风险或需要新权限的动作；三轮仍有重大分歧；需要第二 Expert、追加轮次或扩大预算；外部环境无法由团队恢复。

人工复核不是每个工作项的默认门禁，只在用户预先指定、高风险或上述情况确需用户裁决时触发。

直接用普通回复向用户提问，不调用结构化 ask 工具。信息只保留一次，使用以下短格式：

```text
需要你决定：<一句话问题>
- 当前阶段 / 目标：<一句话>
- 结果：<已经确认的结论>
- 产物：<可定位引用>
- 分歧 / 风险：<只列影响决策的内容>
- Expert 建议：<推荐选项及理由>
请回复：<明确选项或所需信息>
```

说人话，少写过程，不重复背景。内部推理编号、work-item ID 或状态标识只用于定位，不能替代“实现方案”“测试结果”等用户可理解的名称。用户追问技术细节而 Lead 不能从现有裁决证据直接回答时，把问题续派或转发给原 Owner、挑战者或 Expert 回答，Lead 不自行大量探索或猜测。恢复后先记录用户决定，再继续流程。

## 会话交接

在任务制品目录维护简短交接文档，先注册为上下文，再执行 `context rebuild` 刷新索引。至少写明：

- 任务 ID、当前阶段和 revision；
- 当前目标与范围；
- 已完成并验收的事项；
- 进行中的工作项及 Owner；
- blocker、风险与开放问题；
- 关键制品和验证证据路径；
- 下一条可执行动作。

交接文档是索引，不复制大段代码、SPEC 或 Review 正文。
