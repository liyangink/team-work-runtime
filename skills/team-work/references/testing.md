# 测试协作

适用于单元测试、集成测试和 E2E。先明确测试层级、被验证需求、环境约束与成功标准，再决定并行边界。

## 推荐分工

- Junior：梳理行为矩阵、补常规与边界用例、开发夹具、执行测试并保存原始结果。
- Senior：检查覆盖模型、失败路径、隔离性、并发、外部依赖和假阳性；兼任挑战者。
- Expert：可亲自处理高风险领域、复杂并发/一致性、反复失败或关键测试工具；E2E 结果属于核心制品，最终必须由未参与该制品创作的 Expert 复核。

## 单元与集成测试

1. 建立需求到测试的映射，覆盖正常、边界、失败、恢复和兼容路径。
2. 按测试文件、组件或环境划分唯一 Owner；共享夹具由单一 Owner 管理。
3. 先证明测试能捕获目标问题，再确认修复后通过；新增测试不能只重复实现细节。
4. 对失败进行分类：产品缺陷、测试缺陷、环境/网关错误、已知不稳定。保存命令、环境和原始输出。
5. 产品缺陷返回实施环节；测试或夹具缺陷在当前阶段返工；基础设施错误按有界恢复处理。
6. 挑战者复核遗漏行为、脆弱断言、顺序依赖、清理和真实 E2E 路径。

## E2E 小循环

E2E 先判断适用性和环境。适用时用独立 work item 表达以下小循环，不增加顶层研发阶段：

1. 测试设计：确定真实用户路径、边界、环境和成功标准；
2. 用例审查：挑战遗漏路径、不可复现前提和错误断言；
3. 夹具/脚本实现：由唯一 Owner 开发数据、环境和自动化；
4. 实现审查：检查隔离性、清理、可重复性和观测证据；
5. 执行：保存命令、环境标识和原始结果；
6. 结果复核：区分产品缺陷、E2E 制品缺陷、测试策略缺口和环境问题。

用例、夹具、脚本或执行问题留在 E2E 小循环；产品代码缺陷返回实施；只有系统性的上游测试策略缺口返回测试；环境问题在 E2E 阻塞并说明恢复条件。

## 验收

制品至少包含测试代码或夹具、覆盖说明、执行命令、原始结果位置、失败归因、已知未覆盖项和建议结果。仅报告“测试通过”不构成证据。
