# 明晰表达公共规范

本文件是面向人的通用表达规则唯一维护源。TWR 自动提取下面必读段；独立写作或审阅读取本文件。两种入口不重复执行，规则不改变任务授权、制品合同或批准权。

## 明晰表达必读

用完整句和自然语言，内部编号/黑话不能代替人能理解的内容，操作所需技术名保留并解释。先给结论、推荐或现在需要人决定的具体问题，再给主要变化、影响与下一步；首次方案明确批准范围，摘要与完整正文同篇。没有新方向选择就直说；重要风险、分歧和证据缺口即使不能形成选择题，也须在入口可见，不藏进附录。

复杂材料说明目标、主要部分及依赖或影响，用最小有用的关系图或表；简单任务一段即可。短简报之后按需提供可定位依据，完整材料给链接，不默认铺完整候选表，不以视觉折叠冒称分层。不强制章节、字数、模板或重要事项数量上限。

结论须由实际来源支持，区分直接事实、推断、未知和未运行的验证；说明相关检索/核验范围，“没找到”不等于不存在，不补造收益、期限、测试或批准。保持原制品与工具合同。

同因发现可以浓缩，但保留原定位、归属、技术结论、证据及各自处置，不能合并掉不同包或不同关闭状态。报告先说约定交付是否满足及重要未关闭项，不复述工作流水；汇总者不改成员技术结论。

修订说明本轮改变、依据及对原结论的影响，未变部分引用；比较前版或批准先核对真实来源，缺失就说明。作者发送前检查结论、未知、依据、范围与下一步是否清楚；只影响排版偏好的意见不新增返工或轮次。在现有授权内闭环细节，不靠表达改变范围或取得批准。

范围、必要性或修法授权的实质争议，经现成证据仍不能消解时，先暂停依赖工作请用户确认，不耗新一轮或先造新方案来证明必须扩范围。

## 按材料选择阅读重点

使用上面必读段，不另套固定模板：

| 材料 | 读者首先需要知道 | 按需依据 |
| --- | --- | --- |
| 调研 | 原问题、证实与未知、当前可支持的判断 | 来源、检索范围、尚需验证的前提 |
| 方案 | 推荐方向、完整修改与影响、关键取舍和代价 | 约束、接口、顺序敏感动作、失败恢复与验收 |
| 审查 | 对象和约定范围、结论与验收影响 | 发现的触发条件、归属、原证据和处置 |
| 汇报 | 本轮变化、阻碍及具体下一步 | 已有制品、报告、验证结果与比较基线 |

标题提供导航；关系图应解释部分之间怎样影响，不能用目录代替关系。用普通 Markdown 和可访问链接即可，不依赖专用前端。用户明确格式及机器制品合同优先，保留必读段要求的重要信息。

关键选择或核心阻碍的审阅规则见 [明晰审阅](../clarity-review/references/review-rules.md)，普通写作无需加载独立账本、示例或整套团队流程。
