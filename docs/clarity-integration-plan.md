整套能力使用 clarity 名称：`clarity-writing`（明晰表达）、`clarity-review`（明晰审阅）和公共资源 `clarity-guidance`。审阅涵盖重要取舍与核心阻碍，不缩减原定技术检查范围，不代替技术审查或测试。

| 公共输出规范 | 结论前置、阅读层次、关系、证据呈现和修订表达，是通用表达的唯一正文 |
| clarity-writing（明晰表达） | 为人类组织方案、调研、审查报告和汇报，读取公共规范后写作与自检 |

| TWR | 范围、验收、成员报告、审查链、推进和人工批准，保持唯一权威事实来源 |

## 三、公共规范与入口使用

### 公共规范只定义怎样表达

复杂材料先给结论、推荐或具体问题，再说明关系和取舍，最后给可定位依据；简单任务可以一段完成。重要风险、证据不足与未确认前提在入口可见，完整修改和影响仍能找到。摘要与正文使用同一事实，不成为第二份批准基线。

关系地图解释目标、主要部分、依赖、数据流或影响，标题只负责导航。有收益时使用最小有用的表或图，不强制三层、章节、字数或模板；普通 Markdown 即可阅读，不做折叠 UI。

按当前决定的重要性组织“需要决定、需要知道、按需依据”，不新增机器等级字段。重大偏离和证据缺口不因低置信或篇幅而消失；事实、推断和未知分清，不补造收益、概率、测试或时限。

不同产物调整重点：调研说明已证实与未知，方案说明推荐、取舍及完整影响，审查报告说明对象、结论和未关闭问题，汇报说明变化、阻碍与下一步。原制品和工具合同保持。

同因发现可合并呈现，但保留原定位、归属、技术结论、处置与证据，不合并掉不同包或不同关闭情况。修订说明变化及影响；比较或引用批准前核对真实来源，缺失就说明。作者自检关注理解、事实、依据与范围，不以排版偏好新增返工。

### 两个入口按实际需要选择

独立使用时，普通面向人类的产物走写作入口，生成前读取实际选中源的公共规范；同一上下文可复用，来源/内容变化或新会话重读。TWR 正式工作按第五节自动送达短段，不要求调用 skill；代码注释、日志或机械回执不额外加载完整技能。

用户要确认关键选择、核心阻碍、方向偏离或版本增量时使用审阅入口，直接读取公共规范。先确定产物、范围、原始意图与比较基线，扫描 R01–R09 的全部重要候选，包括遗漏和弱化。每项读取足以判断的原始证据，记录真实版本、定位与短摘录；缺证据保留高影响未知，不把作者自评、链接存在或覆盖统计当证明。

先查已确认基线及授权范围内的事实，再给候选一个本轮主去向：

| 去向 | 处理 |
| --- | --- |
| 依据基线可消解 | 已有明确方向的偏离交纠偏或报告，不重新请人选择原方向；仅在修复已获授权时落实 |
| 代理待核查 | 写已查范围、下一动作与升级条件；先查现有监控、工具和证据，不默认重建 |
| 责任方执行项 | 记录责任角色、动作、完成条件；角色未知就标未知，不自行招人或联系他人 |
| 条件触发项 | 记录触发和最晚准备阶段/条件；关键预案在门槛前可见，不等事故发生，不猜分钟截止 |
| 人工方向决策 | 足够证据仍有真实取舍，属于当前审核人的职责，且当前或最近准备阶段需要其选择 |

五去向只是语义引导，不新增 Runtime 枚举、字段、调度或阶段；TWR 的本轮阻塞、非阻塞及范围外分流仍是业务权威，clarity 不覆写。审阅授权不因为能修就变成修复授权。

方向选择与核心阻碍独立：重大安全、数据或可执行性未知即使没有选择题，也要首屏说明现状、影响、核查者与升级条件。“代理待核查”不隐藏风险或扩大授权。人工选择附建议、备选、后果与直接支持判断的证据；阻碍写动作与进入条件，不用“接受” checkbox。

短简报先说当前方向选择、主要变化与核心阻碍，再按需给证据。当前重要事项没有五项或其他机械上限，重复症状可合并，但不遗漏阻碍或各项处置。普通报告无新方向选择就给结论，不凑 checkbox。完整候选、已确认项与执行/条件项留在相应资料中并给链接，不默认紧接首屏总表，不以 Markdown 视觉折叠冒称分层。

方向反馈、修改落实、产物符合性、证据/测试验证分别解释：要求修改不等于接受新版，改完、相符或测试通过也不等于接受。沿已确认方向落实纠偏且无新取舍时，报结果复核或未验证部分，不再询问旧选择；实际新增取舍才提新决定。展示不等于已读，明确接受也不授权部署。使用原接受前核对其范围与条件。

## 四、TWR 批准与独立记录

### TWR 使用现有方案和事实

TWR 模式必须有明确任务、阶段和当前范围上下文，不凭仓库名猜测。已知在 TWR 但事实不可取得时，说明未知并取得可用依据，不静默转独立模式保存第二套记录。

现有人工决定/阻塞卡自动带审阅短段；重大范围变化仍按原报告和用户批准处理，Runtime 不扫描自由文本判偏离。成员按角色/场景接收适用段，不强制调用完整技能。自主核查限当前授权及既有 Owner、Challenger、Expert 职责，Lead 只核对/转述，不修技术或改成员结论，不增角色/轮次。准备决定材料前可做获授权核查；awaiting-user 静止后不派发、主动调查、轮询、代答或推进，须新用户输入恢复。

完整方案仍是唯一人工批准正文，不拆成第二基线。完整候选、分流、证据与待确认比较留在原授权报告或未批准方案正文，简报引用这些和任务事实，深看给现有报告/方案链接，不复制独立账本。批准后普通反馈、阅读与阶段记录引用用户决定事实或已有适当报告，不为记账改写已登记/批准正文及正式评审链；索引不进 CLI，不增权威文件或 schema，不声称 Runtime 维护逐项 ID/revision。

四类事实只按已有用户决定、制品、报告和真实测试资料分别解释，缺证据标未验证，不声称 Runtime 新增四维状态。逐项接受不自动调用 `tw decide`，不等于整阶段批准或部署授权；已有明确整份方案批准可作对应范围依据，不代表逐项已读、不能自动全勾。要求修改不是接受新版，恢复不迁入独立账本。

无新方向决定、纠偏已落实或语义等价均不跳过现版人工批准或重批：登记制品/评审链指纹变化仍由原门检查。本次不改变 humanDecisionFresh，不以语义比较豁免指纹变化；批准后正文冻结，真实需求、范围或方向变化才修订并走原重批。历史问题沿原分流，不自动阻塞、修复或扩入本轮。

### 独立审核保留恢复能力

独立审阅默认沿用原记录，同一问题保留稳定 ID，语义修订升 revision，保留拆分、合并、替代及撤回关系，不按清单顺序继承接受。账本完整记录以下语义，不规定新的 JSON/YAML 实现：

| 记录 | 内容 |
| --- | --- |
| 身份与来源 | 对象、范围、规则版本、ID/revision/原文/类型/适用条件、意图与比较基线、实际内容快照、证据定位/摘录/依赖及未查范围 |
| 去向与行动 | 五去向、影响、证据状态、核心阻碍标记、责任角色和动作、触发条件与最晚准备阶段/条件 |
| 反馈与四类事实 | 反馈原句、可取得的身份、修订/范围/条件；方向、修改落实、符合性、证据和测试验证分别保留，不覆盖旧批准 |
| 展示与恢复 | 已展示修订、有反馈范围、代理核查证据、下一进入条件；展示不等于已读或接受 |

有待处理项、反馈或历史就默认在本任务已授权位置持久保存，每次更新后再报告可恢复状态。短简报与完整账本分开，给账本链接；无授权位置或保存失败时说明限制，提供独立恢复入口，确实无法分离才在简报之后清楚分隔附记录，不遮首屏、不扩大写权限。

收到反馈或恢复前重读当前产物与原记录，核对快照和依赖，重算受影响项与简报；如呈现数量必须重新核对，不手抄旧标题，也不强求每份报告统计。要求修改、文字已改、核对相符、明确接受新版分别保存；落实纠偏且无新取舍时不继续叫“待决定”。条件/执行项到最晚准备门槛仍不可执行就显示阻碍；补证据解除阻碍后更新，不沿旧标记。

等价措辞或无关修改经核对可保留原选择，实质/依赖变化定向重审；消失项保留历史并核对义务，无法对应语义不继承接受。规则升级重扫候选，不清空批准；缺字段不反推实现或测试已过。快照无法核实只报历史视图或当前待核，不沿用旧接受作为现版批准。历史遗失不编造，接受从不授权部署。独立记录不作 TWR 凭证，不迁历史 task。

## 五、发布、装载与 TWR 入口

### 唯一根包与 DSH 注册

根发布清单加入两个新技能目录和公共目录，与已有 team-work 同包发布。仍只产出根包，版本不自动提高，不增框架、脚本、子包或运行时依赖。

注册三个已知技能，遵循宿主来源优先级和重复处理，不改写个人或项目文件。包内运行期条目可能遮蔽同层同名用户来源，实际以返回的 provider、资源基址及可核验目录来源为准，不新增避让策略或强制旧源生效。三条读取、注册与释放独立处理，失败不让其他技能或 tw/tw-dispatch 消失；收拢 disposer，禁用/重载仅释放本插件实际条目。现 skills 服务装配边界保持，单条失败隔离不代表可移除整个服务，不改 inject 必需/可选契约。

随包三技能统一以技能根为 resourceBase，核对 team-work 原 references/... 链接兼容；两个新入口使用相邻公共路径和专项路径，使包内注册与 filesystem provider 布局一致。若 config.skillDir 显式指定自定义 team-work 目录，沿用其原 references 基址语义，不能未经核验改为根目录。两个新技能和公共资源仍来自包，不据自定义目录猜路径，也不新增配置参数。

注册是独立使用的发现入口，以工具返回的正文、provider 和基址核对来源；变化后重读。TWR 自动带入不消费宿主同名目录，固定使用当前根包资源；两者不拼接成新规范。

### init 只处理四个明确目标

装载三个已知技能目录及一个公共文件：

- `.dsh/skills/team-work-v3/`
- `.dsh/skills/clarity-writing/`
- `.dsh/skills/clarity-review/`
- `.dsh/skills/clarity-guidance/output-standard.md`

默认逐项保留已有目标，不能因缺 SKILL.md 就删除已有目录。force 帮助说明只覆盖四目标，不清理技能根、不覆盖整个公共目录。解析目标与父路径；符号链接等造成越项目根时明确拒绝该项，不扩成扫描或清理。

先暂存验证再替换，失败保留最后有效文件，不回滚无关用户文件。原结果 skill 字段兼容，新增 writingSkill、reviewSkill、outputStandard，逐项说明安装、跳过或不可用。部分失败、公共依赖缺失和版本混用明确诊断，不猜用户版本兼容、不把资源存在说成同版，不要求四项目标全局事务或新安装模块。

不创建模型配置或任务事实，不新增命令或来源配置参数。存量副本默认保留，用户后续明确覆盖或合并；新会话、来源变化后重读。

### 同源必读段与选择

公共 output-standard.md 和专项 review-rules.md 各设一对唯一显式起止标记，标记之间为短必读正文；Runtime 提取原文，不另存摘要副本。详细解释引用该段，同一规则只维护一处。公共段包含报告浓缩与证据边界，专项段包含候选分流、核心阻碍、四类事实、授权和 TWR 批准/等待边界，不加载独立账本规则或示例。

读取和选择内聚在已有 guidance.mjs，固定从根包上述两文件按需读取，不依赖 skills API，无跨会话“已读”标记或新配置。项目角色/场景覆盖按原规则保留，不替换包规范源。不调用 skill 工具仍自动带入；深看提供准确包资源路径，只读引用文件，不扩扫描权限。

| 消费方与场景 | 自动带入 |
| --- | --- |
| 所有正式成员 | 最小公共段，覆盖其面向人的产物及报告浓缩 |

| deliver/review 机械回执、agent-map、配置等 | 不重复附段，成员报告规则已随派单送达 |

### 成员消息、Lead 结果和终端同时覆盖

Runtime 以拟议只读输出 requiredGuidance 提供短正文、准确资源路由及来源诊断，不索要模型参数、不写任务事实。投影从 dispatchCard 贯穿 waves/inflight 到 tw-dispatch 每条实际投递。业务 prompt/promptFull 不拼入新规则；DSH 在同一次投递中追加一个规则 text 块，内含适用段。初派、增量续派、全量投递、断链重建及已收本轮正文后的冷 reminder 都如此，规则不另发消息。

coldSessionReceived 继续只匹配原业务块，单独规则更新不变成“未收单”，不剥离正文 marker 对账；若迁移确实改变原角色/场景业务正文，沿原算法处理，不承诺仍是轻提醒。保留会话 ID、登记、防重复判定和恢复路径选择；prompt 两变体互斥，reminder 不补全派单，live 继续零消息，不为更新催单。既有冷重试测试已覆盖业务和宿主引导分块的匹配，但真实 start/send/persist 保留分块与恢复读取仍须隔离验收。

Lead 卡片复用 presentation 的沟通目的并携带适用原文段，继续使用 progress 事实。tw 最终 JSON 的顶层/嵌套卡片与计划按实际消息选一处承载，不重复同段；CLI 人读派单及 stop/human 同源组装，不只在 JSON 出口补字段、不让模型手拼。tw-dispatch 正常派发及 wait-inflight 处置后的最终返回/render 透传 Lead 规则，不丢 presentation，不复制所有成员段或原 waves。

只保证 TWR 实际组装、投递与工具返回，不增加 LLM 汇报拦截，不承诺工具外纯聊天或原生只读助手自动覆盖。awaiting-user 仅呈现规则，绝不因此调查、派发或推进。

### 成本与降级可核验

每条实际消息每个适用段至多一次、最多两段；同操作每份适用资源按需读一次，不加载完整 skill、示例或独立账。两段是发送上限，不是重要问题展示上限，不为长度检查截断风险。源更新在后续正常操作重新读取，不追改历史或发 live 消息刷新；Lead 结果只留自身段。报告关键消息新增段数和长度，与当前派单/呈现文本比较；无宿主 token 计数就报字符/字节，不编 token 或节省百分比，不以 skill 调用次数证明。

缺资源、坏标记、读取拒绝均带准确来源和修复诊断，经所到消息/卡片可见；不能谎称已带入，不硬编码备用长规则，不增死门或降级原合同。仍保持六个新文件，无新 Module、tool、service 或依赖。
