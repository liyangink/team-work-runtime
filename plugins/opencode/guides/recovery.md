# OpenCode 恢复指南

- 网关限流、容量不足或 API 失败不会自动破坏任务状态。保留已有制品和错误证据，再调用 `workflow_run`；Harness 会依据持久操作记录判断重试、恢复原 child session 或返回可执行问题。
- Lead 会话或 OpenCode 进程重启后，先用 `workflow_open mode=resume` 和明确 `task_id` 打开已有任务，或在已有会话绑定上调用 `workflow_run`。不要凭聊天描述猜 session，也不要手工创建替代成员。
- 工具参数错误只说明意图输入不合法，不代表成员会话或网关失效；按返回的问题修正一次，不启动降级、容灾或重复调度。
- 已确认失联的成员由 Harness 保留历史尝试并受控替换；同一档位重试、成本升级和用户介入仍遵循 Team-work 通用恢复规则。
- 人工等待期间不启动后台任务、定时检查或状态轮询。用户新消息到达后，由 `workflow_run` 消费已验证决定并继续。
- 项目标记（`.team-work/project.json`）缺失或属于 v1 遗留目录时，普通会话不受影响；触发工作流后 `workflow_open` 会自动初始化标记，v1 遗留数据保持不动。标记损坏或版本不符时工作流入口会返回修复问题卡片：备份并移除该文件后重新 `workflow_open` 即可自动重建。
